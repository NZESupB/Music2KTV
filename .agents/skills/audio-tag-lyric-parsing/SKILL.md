# 音频标签与歌词解析

用纯代码解析音频容器里的文本标签（ID3v2、FLAC Vorbis Comment）和歌词文本（标准 LRC、增强 LRC、网易云 YRC、ID3 SYLT），并输出统一的行 + 逐字时间模型。
本技能只覆盖“读取与归一化”。它不做标签写入、不做音频解码、不负责渲染染色（渲染只需消费 `LyricLine(startMs, endMs, text, words)`）。

## 何时使用 (When to Use)

触发场景：

- “给播放器加歌词显示，LRC 解析怎么写”
- “ID3v2.4 帧长度读出来特别大 / 读到垃圾数据”
- “SYLT 怎么拆成一行行歌词”
- “网易云 YRC 的 `[起始ms,时长ms](字起始ms,字时长ms,0)` 怎么解析”
- “没有二进制样本文件，怎么测标签解析”

不要用：

- 需要写回/修改标签（本技能只读）；
- 需要音频解码、波形或频谱计算；
- 需要从网络接口拉取歌词（这里只管本地字节/文本）；
- 只是排版/滚动动画问题。

## 工作流程 (Procedure)

1. **先定统一模型**。`LyricLine(startMs, endMs, text, words: List<LyricWord>)`，`LyricWord(startMs, endMs, text)`；无逐字数据时 `words` 为空列表，行级染色即可。解析结果带 `synced: Boolean` 与 `metadata: Map<String,String>`。

2. **歌词格式探测：先 YRC，再 LRC**。读入后先 `text.removePrefix("\uFEFF")` 去 BOM，再按行判断是否有任一行匹配 YRC 行正则，命中则整体走 YRC 分支，不要逐行混用两套规则。

3. **标准 LRC 用“循环剥离前导时间戳”**，因为一行可有多个时间戳（副歌复用）：
   - 时间戳 `\[(\d{1,3}):(\d{1,2})(?:[.:](\d{1,3}))?]`（同时接受 `[mm:ss.xx]`、`[mm:ss.xxx]`、`[mm:ss]`）
   - 每剥一个就生成 `(startMs, rest)` 一条；剥不动且整行匹配元信息 `^\[([a-zA-Z#]+):(.*)]\s*$` 则收进 metadata（键小写）。

4. **`[offset:]` 语义**：正值表示歌词提前。`startMs` 与行结束时间统一减 offset；解析 `removePrefix("+").toLongOrNull() ?: 0L`。

5. **行结束时间 = 下一行开始**，但用 `MAX_LINE_MS = 10_000L` 封顶，避免长间奏让染色停在半句。最后一行没有下一行时同样走封顶逻辑。

6. **增强 LRC（A2）在行内切词**：词标签 `<(\d{1,3}):(\d{1,2})(?:[.:](\d{1,3}))?>`。若第一个 `<tag>` 之前有非空文本，先以行首时间为起点生成一个词；后续每词结束时间取下一个词起点，末词取行结束时间。有逐字数据时 `text` 也由 words 拼接，保证与 words 一致。

7. **YRC**：行 `^\[(\d+),(\d+)](.*)$`（起始ms, 时长ms），词 `\((\d+),(\d+),-?\d+\)`（字起始ms, 字时长ms，第三段为 0 或 -1，忽略）。时间单位就是毫秒，不要再乘 10。

8. **SYLT**：字段顺序固定为 编码字节 → 3 字节语言 → 时间格式（2=毫秒）→ 内容类型（1=歌词）→ 描述（编码终止符结束）→ 循环 `文本 + 终止符 + int32 时间戳`。按“文本以 `\n`/`\r` 开头即换行”分组；组内多于 1 片才生成 words，单片只当整行。

9. **ID3v2 帧遍历**：v2.4 帧大小为 synchsafe，v2.3/v2.2 为普通 int32；两者用错一定读出巨大长度。synchsafe 编码：`(v shr 21 and 0x7F)`, `(v shr 14 and 0x7F)`, `(v shr 7 and 0x7F)`, `(v and 0x7F)`。文本帧编码字节：1 → `FF FE` + UTF-16LE，2 → UTF-16BE，3 → UTF-8，其余 ISO-8859-1。

10. **测试用代码拼字节**：写一个 `TagFixtures`，用 `ByteArrayOutputStream` 按规范拼 `ID3` 头 + 帧 + padding、FLAC 块、MP3 帧，不提交二进制样本文件。字节布局细节见 `references/byte-layouts.md`。

## 陷阱 (Pitfalls)

- **`[mm:ss.xx]` 的 `xx` 是百分秒还是毫秒**：两位按百分秒（×10），三位按毫秒。统一用位数判断，否则整体偏快/偏慢 10 倍。
- **一行多时间戳会产出重复文本**：必须在收集完后按 start 排序，并去掉首尾空行，否则会出现重复行与空行渲染。
- **把元信息行当歌词**：`[ti:]`/`[ar:]`/`[by:]` 没有数字时间戳，但仍可能被宽松正则命中；先剥时间戳、剥不到才尝试元信息，顺序反了会丢元信息或造出时间 0 的歌词。
- **整行无时间戳就当纯文本歌词**：所有行都没有时间戳时应返回 `synced = false` 且所有行 `start=0`，不要抛出异常。
- **末行无限长**：没有下一行时间就取 `MAX_LINE_MS`，不要取 `Long.MAX_VALUE` 或歌曲总时长。
- **ID3v2.4 用 int32 读帧长**：得到超大值后循坏直接越界或死循环。判断 `major >= 4` 才用 synchsafe。
- **APIC 描述字段**：`编码字节 + mime + 0x00 + 图片类型 + 描述 + 终止符 + 数据`，描述终止符按编码决定 1 或 2 字节；漏掉终止符会把图片类型当图片数据。
- **MP3 帧长公式选错层**：MPEG1 Layer III 是 `144 * bitrate / sampleRate`（128kbps/44.1kHz → 417 字节）。Layer I 用 12、Layer II 用 144 但样本数不同，混淆会切错帧边界。
- **Xing 头偏移**：MPEG1 立体声在帧头后 4+32 字节处找 `Xing`，读 flags 后才是帧数；偏移固定写 36 只对部分版本成立。
- **只编译不测试**：编译通过不代表字节偏移正确，必须用 fixture 断言实际数值。

## 验证 (Verification)

运行 engine 模块单元测试，断言下列具体数值全部成立：MP3 fixture `count=3, xingFrames=3` 时帧长为 `144 * 128_000 / 44_100 == 417`、由 Xing 帧数推得的时长与期望一致；`[00:01.00]<00:01.00>字<00:01.50>字` 解析出一行两词且首词 start=1000ms；含 `[offset:-500]` 的样本每行 start 整体 +500ms；SYLT fixture 按换行分组后行数与输入行数相等。
